# داشبورد مدیریتی دفتر درآمد

> **نسخهٔ معماری ۲ (۶۰-۸):** منطق، فرمول‌ها، شاخص‌ها و خروجی‌ها دقیقاً مثل قبل است؛ فقط معماری، Cache، به‌روزرسانی داده و سرعت بارگذاری بهتر شده است.
> بخش‌های پایین‌تر این فایل، تاریخچهٔ تغییرات عملکردی نسخه‌های قبل است و همچنان معتبرند (فقط مسیر فایل‌ها طبق «ساختار پروژه» زیر جابه‌جا شده است: `js/modules/*` ← `js/engines|filters|settings/*`).

## به‌روزرسانی فایل Excel (بدون تغییر JavaScript)

1. فایل `data/1520.xlsx` را با نسخهٔ جدید (همان نام) جایگزین کنید.
2. `node tools/build-manifest.mjs` را اجرا کنید (یا بگذارید GitHub Action این کار را بکند) و commit/deploy کنید.
3. کاربر روی کلید **به‌روزرسانی** (همان کلید قبلی بالای صفحه) می‌زند؛ برنامه Manifest را می‌خواند، تغییر hash را می‌بیند، فایل را می‌گیرد، در Worker پردازش و اعتبارسنجی می‌کند، در IndexedDB ذخیره و همه‌چیز (از جمله «روز سپری‌شده از سال» از تاریخ پایان جدید) را دوباره محاسبه می‌کند.

اگر فراموش کنید Manifest را به‌روز کنید، کلید به‌روزرسانی اثرانگشت HTTP فایل (ETag/Last-Modified/اندازه) را هم می‌سنجد و تغییر را تشخیص می‌دهد و داده جدید اعمال می‌شود؛ فقط هشدار «manifest.json قدیمی است» نشان داده می‌شود.
در این حالت برنامه Manifest قدیمی را به‌خاطر می‌سپارد (`staleManifestHash`) و در بازشدن‌های بعدی به‌جای دانلود مجدد Excel فقط اثرانگشت HTTP را می‌سنجد. با اجرای `node tools/build-manifest.mjs` و انتشار Manifest تازه، هشدار برای همیشه برطرف می‌شود.

## Manifest و Cache

- `data/manifest.json`: به‌ازای هر Dataset، `version` و `hash` (SHA-256). فقط چند صد بایت است و هر بار باز شدن برنامه خوانده می‌شود.
- **IndexedDB** (`dashboard-data`): داده پردازش‌شده + hash + نسخه. با باز شدن برنامه، اگر Cache معتبر باشد داشبورد **بلافاصله** و بدون دانلود/پارس Excel نمایش داده می‌شود و بعد در پس‌زمینه Manifest بررسی می‌شود.
- LocalStorage فقط برای تنظیمات (آستانه‌ها) است.
- Cache محاسباتی موتور مالی با `datasetVersion` کلید می‌خورد؛ بعد از Update موفق هرگز نتیجهٔ داده قدیمی نمایش داده نمی‌شود.
- با تغییر منطق خوانش/نرمال‌سازی، `version` در `processors/report1520.js` را بالا ببرید تا Cache قدیمی خودکار باطل شود.

## اعتبارسنجی (Dataset خراب جایگزین Dataset سالم نمی‌شود)

رد می‌شود (و داده سالم قبلی + پیام خطای واضح حفظ می‌شود): فایل خراب/ناخوانا · Sheet نیست · ستون ضروری حذف شده · رکوردی نیست · تعداد رکوردها نسبت به نسخهٔ قبل غیرعادی (کمتر از نصف یا بیش از دو برابر؛ برای تغییر عمدی `"allowCountChange": true` را در manifest بگذارید) · سلول‌های عددی نامعتبر · بازهٔ تاریخ گزارش نامعتبر.
اولین بار (بدون Cache) فقط خطاهای «fatal» مانع می‌شوند و بقیه به‌صورت هشدار نمایش داده می‌شوند.

## Web Worker

`dataWorker.js` فقط Read/Parse/Normalize/Validate را انجام می‌دهد؛ هیچ Business Logic یا امتیازدهی‌ای در آن نیست (موتورها روی Main Thread و با همان کد قبلی اجرا می‌شوند). کتابخانهٔ XLSX فقط داخل Worker بارگذاری می‌شود. اگر Worker در مرورگر نباشد، همان خط لوله روی Main Thread اجرا می‌شود.

## Lazy Loading

تب‌های «رتبه»، «مصرف»، «مالی» و «گزارش» (و موتورشان) فقط هنگام اولین ورود Load می‌شوند؛ حجم JS اولیه حدود ۴۵٪ کمتر است. Chart.js حذف شد (در کد استفاده نمی‌شد).

## فیلترها بعد از Update

بعد از دریافت داده جدید، فقط **انتخاب‌های فیلتر** (امور/کاربری/شهر) که در داده جدید وجود ندارند برداشته می‌شوند و پیامی نشان داده می‌شود؛ هیچ داده‌ای حذف نمی‌شود. انتخاب‌هایی که در داده جدید هست حفظ می‌شود.

## افزودن Dataset جدید

1. فایل را در `data/` بگذارید (مثلاً `data/reading.xlsx`).
2. در `js/data/dataRegistry.js`: یک ورودی در `DATASETS` و یک خط در `PROCESSORS` اضافه کنید.
3. `js/data/processors/reading.js` را بسازید (`version`، `process(raw)`، `validate(processed, raw, ctx)`؛ الگو: `report1520.js`).
4. `node tools/build-manifest.mjs` — Engineهای قبلی تغییر نمی‌کنند. (اتصال Dataset جدید به یک تب جدید، کار UI همان تب است.)

## Deploy روی GitHub Pages / Static Hosting

- همهٔ مسیرها نسبی‌اند و نسبت به محل خود فایل‌ها حل می‌شوند، پس زیرمسیر `https://user.github.io/<repo>/` بدون تنظیم کار می‌کند (تست‌شده).
- Settings → Pages → Deploy from branch (ریشهٔ repo) یا استفاده از `.github/workflows/pages.yml`. فایل `.nojekyll` موجود است.
- برای اجرای محلی: `npx serve .` (باز کردن مستقیم با `file://` به‌خاطر Worker/fetch کار نمی‌کند).
- **vendor/ (اختیاری):** `node tools/fetch-vendor.mjs` را یک بار اجرا و پوشهٔ `vendor/` را commit کنید تا برنامه به CDN وابسته نباشد. بدون آن، خودکار از CDN می‌گیرد.
- **GitHub Action (اختیاری):** `update-manifest.yml` با تغییر `data/*.xlsx`، manifest را به‌روز و commit می‌کند. اجرای برنامه به آن وابسته نیست.
- PWA: بخش بعدی.

## PWA (نصب روی موبایل/دسکتاپ و اجرای آفلاین)

- `manifest.webmanifest` + `icons/` + `sw.js` + `js/core/pwa.js`. برنامه از منوی مرورگر «Install / افزودن به صفحهٔ اصلی» نصب می‌شود (نیازمند https؛ GitHub Pages است).
- **Service Worker فقط پوستهٔ برنامه** (HTML/CSS/JS/فونت/آیکن/نقشه) را نگه می‌دارد تا آفلاین هم باز شود؛ داده از IndexedDB خوانده می‌شود، پس آفلاین هم همهٔ تب‌ها کار می‌کنند.
- **داده هرگز در Service Worker Cache نمی‌شود:** هر درخواست زیر `data/` (Excel و `manifest.json`) اصلاً توسط SW مدیریت نمی‌شود و مستقیم به شبکه می‌رود. تشخیص تغییر داده فقط با Manifest/hash و IndexedDB است؛ بنابراین Excel قدیمی هرگز «برای همیشه» Cache نمی‌ماند.
- **کد همیشه تازه است:** فایل‌های HTML/CSS/JS با روش network-first (درخواست شرطی ETag، ارزان) گرفته می‌شوند و فقط وقتی شبکه نیست از Cache می‌آیند؛ فونت/تصویر Cache-first هستند. آیکن‌های Lucide از CDN هم برای آفلاین Cache می‌شوند.
- **به‌روزرسانی SW:** `node tools/build-pwa.mjs` (در Action هم اجرا می‌شود) لیست Precache و `BUILD` را در `sw.js` می‌نویسد؛ با هر تغییر فایل‌ها `sw.js` عوض می‌شود و مرورگر نسخهٔ جدید را خودکار نصب و Cacheهای قدیمی را پاک می‌کند. بعد از تغییر فایل‌ها آن را یک بار اجرا و `sw.js` را commit کنید (`--check` برای CI).
- اگر در آینده Datasetهای دیگری به `data/` اضافه شد، همان قانون برقرار است (کل پوشهٔ `data/` از SW مستثناست).

## تب «تحلیل توصیفی و هشدارها»

دکمه **تحلیل** در نوار پایین. همان دیتاست و همان فیلترهای جاری (امور / کاربری) را استفاده می‌کند و با هر تغییر فیلتر بدون رفرش دوباره رندر می‌شود. بدون نقشه است.

**چیدمان:** بالای صفحه همان کلیدهای اصلی **آمارها · سرانه‌ها · شاخص‌ها** (مثل هوم) و زیر آن زیرگروه شاخص‌ها.

**سطح‌بندی:** بدون انتخاب امور → تحلیل امورها · یک یا چند امور → شهرهای زیرمجموعه · یک شهر (چیپ‌های «شهر» در همین تب) → کاربری‌های آن شهر.

**بخش‌ها (به ترتیب):** سربرگ محدوده و شاخص · کارت‌های میانگین / برترین / ضعیف‌ترین واحد · خلاصه وضعیت کلی (امتیاز سلامت از ۱۰۰ + جمله‌های پویا) · هشدارهای هوشمند (فیلتر رنگ: بحرانی / هشدار / نکته / عالی) · جدول رتبه‌بندی با کلید **امور/شهرها ⇄ کاربری** · کاربری‌های مهم.

### آستانه‌های استاندارد (برای درصد وصول و دوره وصول مطالبات)
| شاخص | عالی/خوب | قابل‌قبول | هشدار | بحرانی |
|---|---|---|---|---|
| درصد وصول | ≥ ۹۵٪ | ۸۵–۹۵٪ | ۷۰–۸۵٪ | < ۷۰٪ |
| دوره وصول مطالبات | ≤ ۶۰ روز | — | ۶۰–۹۰ روز | > ۹۰ روز |

برای این دو شاخص رتبه‌بندی، تگ وضعیت و هشدارها با همین آستانه‌هاست. برای بقیه شاخص‌های نسبتی (سرانه‌ها، قیمت آب فروش رفته) مقایسه نسبی با میانگین محدوده (بحرانی ≥ ۲۵٪ و هشدار ≥ ۱۲٪ انحراف نامطلوب) و برای شاخص‌های حجمی فقط تمرکز و اختلاف اندازه گزارش می‌شود.

**امتیاز سلامت:** ۶۰٪ درصد وصول + ۴۰٪ دوره وصول مطالبات (مقادیر تجمیعی محدوده = میانگین وزنی بر اساس درآمد)؛ آستانه‌های بالا به امتیاز ۴۰ / ۶۰ / ۸۰ نگاشت می‌شوند.

**هشدارهای مستقل از شاخص:** رشد بدهی (≥ ۳۰٪ نسبت به ابتدای دوره) · تمرکز (۳ واحد برتر بیش از ۵۰٪ درآمد یا بدهی) · ناهماهنگی مصرف و درآمد (قیمت هر مترمکعب بیش از ۱٫۵ انحراف معیار از میانگین) · کاربری‌های مهم با وصول/دوره وصول ضعیف.

**کاربری‌های مهم:** مسکونی، تجاری و مراکز خدمات غیر دولتی، صنعتی، اقامتگاه غیردایمی (بقیه = «سایر»). جدول سهم هر کاربری از مشترک، مصرف، درآمد، وصول و بدهی + درصد وصول و دوره وصول با رنگ وضعیت.

واحدهایی با سهم مشترک کمتر از ۰٫۵٪ در هشدار و انتخاب برترین/ضعیف‌ترین لحاظ نمی‌شوند (در جدول با وضعیت واقعی می‌آیند). همه آستانه‌ها در `CONFIG` و `THRESHOLDS` بالای `js/modules/analyticsEngine.js` هستند.

### تغییرات دیگر
- هوم: کلید پاک‌کن روی گوشه بالا-چپ کانواس نقشه؛ با انتخاب امور روشن می‌شود و انتخاب امور را پاک می‌کند.
- بازشوهای «فیلتر کاربری» و «امور» در موبایل هم‌عرض صفحه باز می‌شوند و صفحه افقی جابه‌جا نمی‌شود.

### فایل‌ها
`js/dashboards/analytics.js` (رابط) · `js/modules/analyticsEngine.js` (منطق) · `js/dashboards/map.js` (خروجی `META`/`calc` + کلید پاک‌کن) · `js/app.js` · `index.html` · `css/main.css` (بلوک `an-*`)

## تب «خروجی» (گزارش چاپی / PDF)

دکمه **خروجی** در نوار پایین. فیلترهای بالای صفحه (کاربری و امور) فقط برای **محاسبات** هستند؛ باقی تنظیمات در همین تب است:

- **ستون‌ها:** سه کلید آمارها / سرانه‌ها / شاخص‌ها (چندانتخابی) و زیر هر کدام چیپ تک‌تک ستون‌ها. ستون‌های انتخابی در تیتر جدول (با نوار رنگی هر گروه و واحد زیر عنوان) می‌آیند.
- **ردیف‌ها:** امور | شهر | کاربری. برای شهر و کاربری، زیر هر امور یک ردیف **«سرجمع امور»** و سپس زیرمجموعه‌ها؛ ردیف آخر «جمع کل». مقادیر سرجمع از محاسبه مستقیم روی داده‌ها می‌آیند (نه جمع نسبت‌ها).
- **مرتب‌سازی:** انتخاب یکی از ستون‌های انتخابی + نزولی/صعودی. در حالت شهر/کاربری امورها بر اساس سرجمع خودشان مرتب می‌شوند و زیرمجموعه‌ها درون هر امور.
- **سربرگ گزارش:** بازه گزارش، تاریخ چاپ (شمسی)، کاربری‌ها («همه کاربری‌ها» اگر فیلتر نباشد)، امور و ستون مرتب‌سازی.
- **جهت صفحه:** خودکار؛ اگر عرض لازم ستون‌ها از عرض A4 عمودی بیشتر شود (بیش از ۷ ستون) صفحه افقی می‌شود؛ با کلید «عمودی/افقی» هم قابل تغییر است. برای ستون‌های زیاد اندازه فونت جدول کوچک می‌شود.
- **شماره صفحه:** پایین هر صفحه به شکل «صفحه ۱ از ۶» (با @page margin box؛ نیازمند Chrome/Edge نسخه ۱۳۱ به بالا).
- **کلید چاپ هشدارها و بحران‌ها:** روشن → خانه‌های «درصد وصول» و «دوره وصول مطالبات» با آستانه استاندارد رنگی می‌شوند (قرمز/نارنجی/سبز) و در انتهای گزارش بخش «هشدارها و بحران‌ها» (موارد بحرانی و هشدار) چاپ می‌شود؛ خاموش → جدول ساده و بدون این بخش.

**گرفتن PDF:** دکمه «چاپ / ذخیره PDF» → در پنجره چاپ مقصد را روی *Save as PDF* بگذارید (رنگ‌ها خودکار چاپ می‌شوند؛ اگر پس‌زمینه‌ها رنگی نبود گزینه *Background graphics* را روشن کنید). فقط برگه گزارش چاپ می‌شود، نه فیلترها و کلیدها.

اعداد در جدول گرد می‌شوند (به‌جز سرانه مصرف با ۲ رقم اعشار و درصد وصول/دوره وصول با ۱ رقم). فایل: `js/dashboards/report.js`.

### به‌روزرسانی‌های اخیر
- **نمره امور:** در تب خروجی، کلید چهارم «نمره امور» ستونی از ۱۰۰ اضافه می‌کند (۶۰٪ درصد وصول + ۴۰٪ دوره وصول مطالبات، برای هر امور/شهر/کاربری روی داده خودش) و در فهرست «مرتب‌سازی بر اساس» هم هست.
- **رنگ‌ها:** تیتر جدول خروجی و ستون‌های درصد وصول، دوره وصول و نمره به سبک شیشه‌ای و طیفی (قرمز ← نارنجی ← زرد ← سبز؛ نقاط شکست = آستانه‌های استاندارد) مثل باکس‌های هوم.
- **عرض ستون اول:** بر اساس بلندترین نام امور/شهر/کاربری تنظیم می‌شود و ستون‌های دیگر مابقی عرض را می‌گیرند.
- **هشدارها (تب تحلیل و خروجی):** یک درجه بزرگ‌تر، شیشه‌ای و طیفی، و دسته‌بندی بر اساس امور: عنوان امور + خط، سپس بحرانی‌ها، هشدارها و نکته‌های همان امور. موارد بدون امور مشخص در «کل محدوده» بالای فهرست می‌آیند. در تب تحلیل امورها بر اساس بیشترین بحران و در خروجی به ترتیب همان جدول هستند.
- **ریبون پایین:** ترتیب امور | تحلیل | **هوم** | خروجی | قرائت (هوم وسط)، همه کوچک‌تر.

## منوی تنظیمات (همبرگری، بالای صفحه کنار رفرش)

همه آستانه‌ها و پارامترهایی که برای وضعیت، نمره و هشدار استفاده می‌شوند از این منو قابل تنظیم‌اند و بلافاصله در تب‌های تحلیل و خروجی اعمال می‌شوند. فقط مقدارهای تغییرداده‌شده در `localStorage` مرورگر ذخیره می‌شوند (کنار هر مورد تغییرکرده کلید ↺ برای بازگشت به پیش‌فرض هست، و پایین منو «بازگردانی همه»).

گروه‌ها: آستانه‌های استاندارد (درصد وصول، دوره وصول) · نمره امور (وزن مؤلفه‌ها، نگاشت به نمره، حدود خوب/قابل‌قبول/هشدار) · مقایسه نسبی واحدها (انحراف بحرانی/هشدار/عالی، حداقل سهم واحد) · هشدارها (هر قانون روشن/خاموش + پارامترهایش: شکاف عملکردی، تمرکز، اختلاف اندازه، رشد بدهی، پارتو، ناهماهنگی قیمت، کاربری‌های مهم) · کاربری‌های مهم (انتخاب چندتایی) · نمایش (تعداد ردیف‌ها).

### توسعه در آینده (بدون دست‌زدن به رابط)
هر چیزی که ثبت شود خودش در منوی تنظیمات می‌آید (`js/modules/settings.js` = رجیستری، `js/modules/settingsMenu.js` = منو، `js/modules/analyticsEngine.js` = ثبت‌ها):

| می‌خواهید | تابع | مثال |
|---|---|---|
| شاخص جدید با آستانه وضعیت | `registerThreshold({metric, label, direction:"higher"\|"lower", unit, levels:[{id:"good"\|"ok"\|"warn", statusLabel, sev, settingLabel, default}]})` | بعد از دو مورد آخر فایل موتور |
| شاخص جدید در نمره امور | `registerScoreComponent({metric, label, weight, span, spanLabel, spanUnit})` (شاخص باید قبلاً `registerThreshold` شده باشد) | — |
| هشدار جدید | `registerAlertRule({id, scope:"struct"\|"general", label, description, params:[...], run(ctx){ return [{sev, text, area?}] }})` | قوانین `gap` و `pareto` را ببینید |
| تنظیم دلخواه | `registerSetting({id, group, label, default, min, max, unit})` و خواندن با `get(id)` | تنظیمات «نمایش» در `analytics.js` |
| گروه جدید منو | `registerGroup({id, label, order})` | — |

- وضعیت، رنگ طیفی خانه‌ها، رتبه‌بندی، متن راهنما و هشدارهای شاخص جدید خودکار از روی آستانه‌ها ساخته می‌شوند. اگر می‌خواهید ستونش در جدول خروجی هم انتخاب‌شدنی باشد، فقط یک مدخل به `COL` و یکی از `GROUPS` در `js/dashboards/report.js` اضافه کنید (و در صورت نیاز فرمول به `META`/`calc` در `map.js`).
- قانون هشدار `scope:"struct"` روی واحدهای شاخص انتخابی اجرا می‌شود (`ctx`: `units, best, worst, benchmark, meta, label, val, size, abs, metric, level, p`)؛ `scope:"general"` مستقل از شاخص است (`ctx`: `rows, units, level, metric, label, areaOf, noun, p`). `ctx.p("نام‌پارامتر")` مقدار جاری تنظیم را می‌دهد. با گذاشتن `area` روی هشدار، در دسته‌بندی «بر اساس امور» قرار می‌گیرد.

نوار بالا هم اکنون در یک سطر و هم‌عرض صفحه است (در موبایل برچسب «روز سپری‌شده از سال» کوتاه می‌شود).

## رنگ نقشه و عرض ستون‌های خروجی

**نقشه (هوم):** هر موضوع طیف رنگ خودش را دارد، مطابق باکس‌های صفحه هوم: تعداد مشترک = آبی‌خاکستری · مصرف (و سرانه/روزانه‌اش) = آبی روشن · درآمد (و سرانه/روزانه، قیمت آب فروش رفته) = کهربایی · وصول (و سرانه/روزانه، درصد وصول) = سبز · بدهی (و سرانه بدهی، دوره وصول) = قرمز. در طیف قرمز «بیشتر = بدتر» است و هرچه پررنگ‌تر، نامطلوب‌تر.
- **راهنما ۴ قسمتی:** برای درصد وصول و دوره وصول، ۴ کلاس بر اساس همان آستانه‌های استاندارد منوی تنظیمات (بحرانی/هشدار/قابل‌قبول/عالی؛ خوب/هشدار/بحرانی/بحرانی شدید — لبه چهارم دوره وصول = آستانه هشدار + فاصله دو آستانه قبلی). برای بقیه شاخص‌ها ۴ کلاس چارکی (کمترین/پایین/بالا/بیشترین). زیر هر کلاس بازه و تعداد امور نوشته می‌شود.
- رنگ‌ها روشن و شیشه‌ای‌اند (گرادیان ملایم با کمی شفافیت، ۴ پله از روشن تا پررنگ در همان طیف). تعریف طیف‌ها: `FAMILY` و `HUES` در `js/dashboards/map.js`.

**جدول خروجی:** عرض هر ستون از طول واقعی عددهای همان ستون (به‌ویژه ردیف‌های سرجمع و جمع که بزرگ‌ترند و پررنگ‌اند) محاسبه می‌شود و اندازه فونت طوری تنظیم می‌شود که هیچ رقمی از خانه بیرون نزند؛ جهت صفحه هم بر همین اساس: اگر در A4 عمودی با فونت خوانا (≥ حدود ۷ نقطه) جا شود عمودی، وگرنه افقی.

### تغییرات ظاهری اخیر
- برچسب نام امورها روی نقشه بزرگ‌تر، پررنگ‌تر و با حاشیه سفید ضخیم‌تر شد (در موبایل هم بزرگ‌تر).
- ریبون پایین: فقط یک مورد روشن است؛ «هوم» هم فقط وقتی فعال است آبی می‌شود (در حالت عادی کمی بزرگ‌تر و خنثی است).
- تب خروجی: بخش‌های تنظیمات با خط از هم جدا شده‌اند (ستون‌ها · ردیف‌ها · مرتب‌سازی · جهت صفحه · هشدار و چاپ)، چهار کلید ستون‌ها در یک سطر، و در برگه گزارش هم بین جدول، راهنمای رنگ و هشدارها خط جداکننده هست.

### فیلتر چرخشی «شهر/روستا» و ردیف «شهر/روستا» در خروجی
- **فیلتر نوار بالا (همه صفحات):** کنار فیلتر امور و کاربری. هر کلیک حالت بعدی: **شهر/روستا** (پیش‌فرض، هر دو) ← **شهر** ← **روستا** ← دوباره هر دو. همه محاسبات (هوم، نقشه، تحلیل، خروجی) بر همان اساس انجام می‌شود. تفکیک شهر/روستا از نام ردیف شهر است: نام‌هایی که با «بخش» شروع شوند روستا هستند (`settlementType` در `dataProcessor.js`).
- **خروجی → ردیف‌ها بر اساس:** سه کلید **امور | شهر/روستا | کاربری** که روشن/خاموش می‌شوند، ولی **فقط ۵ حالت مجاز است**: امور · امور-شهر/روستا · امور-شهر/روستا-کاربری · امور-کاربری · کاربری. ترتیب سطح‌ها ثابت است (امور ← شهر/روستا ← کاربری) و کلیدی که به حالت غیرمجاز برساند غیرفعال (کم‌رنگ) می‌شود (مثلاً «شهر/روستا» بدون امور). تعریف حالت‌ها: `VALID_MODES` در `js/dashboards/report.js`.
  - «شهر/روستا» خودش دو سطح است: «مجموع شهر» و «مجموع روستا» و زیر هرکدام تک‌تک شهرها یا بخش‌ها (روستاها).
  - هر گره والد ردیف سرجمع (سرجمع امور / مجموع شهر / مجموع … ) دارد و زیرمجموعه‌هایش زیرش می‌آید؛ گروه‌ها بر اساس سرجمع خودشان و زیرمجموعه‌ها درون هر گروه بر اساس ستون مرتب‌سازی چیده می‌شوند؛ سطح‌ها با تورفتگی و رنگ ملایم جدا شده‌اند. ردیف آخر «جمع کل».
  - سربرگ گزارش «نوع سکونتگاه» و ترتیب سطح‌ها را می‌نویسد. توجه: حالت امور-شهر/روستا-کاربری حدود ۲۰۰۰ ردیف می‌سازد.
- برچسب امورها روی نقشه یک درجه دیگر بزرگ‌تر شد.

## بازطراحی نوار فیلتر بالای صفحات

نوار فیلتر بالای همه صفحات (هوم، تحلیل، خروجی) اکنون دو ردیف دارد:

### ردیف اول — فیلتر کاربری (۳ کلید در یک سطر)
1. **کلید چرخشی نیروهای مسلح** (`#armedForcesBtn`): با هر کلیک عوض می‌شود — **با نیروی مسلح** (پیش‌فرض، عادی) ← **بدون نیروی مسلح** (این کاربری از همه محاسبات حذف می‌شود) ← **نیروی مسلح** (فقط همین کاربری محاسبه می‌شود) ← دوباره از اول. در هر حالت (حتی هنگام باز/بسته بودن کلید دوم) اعمال می‌شود.
2. **کلید روشن/خاموش «دستگاه‌های اجرایی و فضای سبز»** (`#adminGreenBtn`): روشن → فقط داده‌های کاربری‌های «عمومی و دستگاه‌های اجرایی» و «فضای سبز» محاسبه می‌شود؛ خاموش → بدون اثر. **حالت ویژه:** اگر همزمان کلید نیروهای مسلح روی «نیروی مسلح» باشد، به‌جای تقاطع (که نتیجه خالی می‌داد)، هر سه کاربری با هم (اجتماع) محاسبه می‌شوند — دقیقاً طبق خواسته کاربر، بدون تداخل بین دو کلید.
3. **فیلتر کاربری چندانتخابی قبلی** (دراپ‌داون + پاک‌کن): بدون تغییر در عملکرد چندانتخابی، با یک افزوده: چیپ **«۴ کاربری»** (به‌جای چیپ جداگانه «نیروهای مسلح» که حذف شد، چون کلید ۱ آن را پوشش می‌دهد) که با یک کلیک همان ۴ کاربری تنظیم‌شده در «کاربری‌های مهم» منوی تنظیمات (`usages.important`) را با هم انتخاب/لغو می‌کند؛ قابلیت چندانتخابی معمولی برای بقیه کاربری‌ها دست‌نخورده می‌ماند.

### ردیف دوم — امور و شهر/روستا
- فیلتر **امور** (دراپ‌داون چندانتخابی + پاک‌کن)، بدون تغییر در عملکرد.
- فیلتر **شهر/بخش** (جدید): فقط وقتی دقیقاً یک امور فعال باشد (از دراپ‌داون یا کلیک روی نقشه) ظاهر می‌شود؛ فهرست شهرها و بخش‌های همان امور را چندانتخابی نشان می‌دهد، با پاک‌کن جلوش. با تغییر امور یا رفتن به حالت غیرتکی، خودش پاک و پنهان می‌شود.
- کلید چرخشی **شهر/روستا**، بدون تغییر در عملکرد.

همه این فیلترها در `filteredRows()`/`chartBaseRows()` در `js/app.js` به‌صورت متقاطع اعمال می‌شوند و روی هوم، نقشه، تب تحلیل و تب خروجی یکسان اثر می‌گذارند (چون همه از همین دو تابع مرکزی داده می‌گیرند).

## بازطراحی کامل تب «تحلیل» — داشبورد کارت‌های ثابت

تب تحلیل دیگر شاخص انتخابی ندارد (نوار آمارها/سرانه‌ها/شاخص‌ها روی این تب مخفی است) و به‌جای هشدار/رتبه‌بندی قبلی، ۵ کارت ثابت را بر همان فیلترهای بالای صفحه (کاربری، امور، شهر/بخش، شهر/روستا) نشان می‌دهد:

1. **نمره امور** (۱/۳ عرض): نمره از ۱۰۰ همان فرمول قبلی (منوی تنظیمات)، برچسب وضعیت «عادی / هشدار / بحرانی» و یک توضیح کوتاه علت. با انتخاب **یک** امور، زیرش «نمره استان» و «رتبه امور» (از میان همه امورها، بر مبنای همین نمره) هم اضافه می‌شود.
2. **تعداد مشترک** (۲/۳ عرض): کل، شهر، روستا با درصد نسبت به کل. با انتخاب یک امور، خط «٪ از استان» (کل/شهر/روستا) زیرش باز می‌شود؛ با درون‌رفت به یک شهر/بخش مشخص، همین خط به «٪ از امور» تغییر می‌کند.
3. **مصرف** (آبی): مصرف کل، سرانه مصرف در ماه، قیمت آب فروش‌رفته — هرکدام به تفکیک شهر/روستا. همان قاعده «٪ از استان ⇄ ٪ از امور»؛ برای قیمت، در سطح امور به‌جای درصد، خود «قیمت آب استان» به‌صورت عدد نشان داده می‌شود (چون درصد برای یک نرخ گمراه‌کننده است) و فقط در سطح شهر به درصد نسبت به امور تبدیل می‌شود.
4. **وضعیت مالی**: سه ستون درآمد/وصول/بدهی (رنگ‌های قبلی: کهربایی/سبز/قرمز) — مقدار کل (میلیون ریال) + ٪ از استان یا امور، سرانه مشترک در ماه (ریال)، و متوسط روزانه (میلیون ریال/روز) + ٪ از استان یا امور.
5. **شاخص‌ها**: دوره وصول، درصد جذب (درصد وصول)، و **درصد رشد بدهی** (شاخص جدید، پایین توضیح داده شده) در یک ردیف، با فونت پررنگ و رنگ هرکدام بر اساس وضعیف آستانه استانداردش (سبز/نارنجی/قرمز). با انتخاب یک امور، خط مرجع «استان» زیرش می‌آید؛ با درون‌رفت به یک شهر، خط «امور» هم اضافه می‌شود (در سطح شهر هر سه ردیف — شهر، امور، استان — با هم دیده می‌شوند).

همه این محاسبات از `baseRows` (کل استان با فیلتر کاربری/شهروروستای فعلی، بدون فیلتر امور) به‌عنوان مبنای «٪ از استان» و از زیرمجموعهٔ آن برای «٪ از امور» استفاده می‌کنند؛ فایل: `js/dashboards/analytics.js`.

### شاخص جدید: درصد رشد بدهی
`(بدهی پایان دوره − بدهی ابتدای دوره) ÷ بدهی ابتدای دوره × ۱۰۰`. به‌عنوان یک شاخص کامل به سامانه اضافه شد (نه فقط برای تب تحلیل):
- در نقشه/تب هوم، زیرمجموعه «شاخص‌ها» قابل انتخاب و رنگ‌آمیزی است (`js/dashboards/map.js`، `js/dashboards/overview.js`).
- آستانه استاندارد آن (خوب ≤ ۰٪، هشدار تا ۳۰٪، بحرانی بالاتر) در `js/modules/analyticsEngine.js` ثبت شده و مثل هر شاخص دیگر از **منوی تنظیمات** قابل تغییر است.
- در جدول ستون‌های تب خروجی (report) فعلاً اضافه نشده؛ در صورت نیاز با افزودن یک سطر به `COL`/`GROUPS` در `js/dashboards/report.js` قابل اضافه‌شدن است.

## اصلاحات نوار فیلتر، کارت نمره، و شاخص خروجی

### نوار فیلترهای بالای صفحه
- **ردیف اول (۳ کلید):** نیروهای مسلح (چرخشی؛ **پیش‌فرض «بدون نیروی مسلح»**) · دستگاه‌های اجرایی و فضای سبز (روشن/خاموش، بدون آیکون — فقط یک نقطه رنگی + متن، پیش‌فرض خاموش) · شهر/روستا (بدون تغییر).
- **ردیف دوم (۲ کلید):** امور (+ پاک‌کن) · کاربری (+ پاک‌کن).
- **دراپ‌داون‌های امور و کاربری:** برای رفع مشکل افتادن پشت نوار پایین/بریده‌شدن در صفحه‌های کوتاه، این دو دراپ‌داون هنگام باز شدن به‌صورت پویا (JavaScript) روی صفحه موقعیت‌دهی می‌شوند: همیشه کامل داخل دید (z-index بالا، fit به ارتفاع صفحه، و در صورت نبود جا در پایین به‌صورت خودکار بالای دکمه باز می‌شوند). فهرست کاربری (۹ گزینه) با این تغییر دیگر نیازی به اسکرول ندارد؛ فهرست امور (۳۶ گزینه) در صفحه‌های خیلی کوتاه همچنان می‌تواند داخل خودش اسکرول شود (طبیعی برای این تعداد آیتم).
- **شهر/بخش:** به‌جای دکمه دراپ‌داون جدا، حالا وقتی دقیقاً یک امور انتخاب شود، جعبه چیپ‌های قابل‌انتخاب (چندانتخابی) مستقیماً زیر همان دو کلید، درون نوار فیلتر باز می‌شود — با یک دکمه پاک‌کن کنار عنوانش.

### کارت نمره (تب تحلیل)
نمودار از میله افقی به **حلقه نازک دایره‌ای** تغییر کرد؛ عدد نمره از ۱۰۰ وسط حلقه است. بالای حلقه: نام محدوده (کل استان / نام امور / نام شهر) و رتبه — «رتبه … در استان» وقتی یک امور انتخاب شده، و «رتبه … در امور» وقتی به یک شهر/بخش مشخص درون‌رفت (رتبه‌بندی شهرها این‌بار فقط میان شهرهای همان امور است، نه کل استان). کنار نام، برچسب وضعیت (عادی/هشدار/بحرانی). کنار حلقه، توضیح کوتاه علت وضعیت.

### شاخص «درصد رشد بدهی» در تب خروجی
این شاخص (که در نوبت قبل به نقشه/صفحه هوم اضافه شده بود) حالا به گروه «شاخص‌ها»ی تب خروجی هم اضافه شد: قابل انتخاب به‌عنوان ستون گزارش (پیش‌فرض روشن)، قابل انتخاب برای مرتب‌سازی، و رنگ‌آمیزی شیشه‌ای طیفی‌اش هم مثل بقیه شاخص‌های دارای آستانه استاندارد کار می‌کند.

## تب «ناهنجاری» — تحلیل سه‌سطحی (نسخهٔ ۲)

هر رکورد (استان + امور + شهر + کاربری) هم‌زمان سه تحلیل مستقل دارد: `provinceAnalysis` (Province Benchmark) · `affairsAnalysis` (Affairs Benchmark) · `cityAnalysis` (City Internal Benchmark). فیلترها فقط View می‌سازند و آمار را تغییر نمی‌دهند.

- فایل‌ها: `js/modules/anomalyEngine.js` (محاسبات + تنظیمات + قرارداد خروجی) · `js/dashboards/anomaly.js` (UI) · انتهای `css/main.css` (فقط سلکتورهای `.an-*`) · یک خط در `js/app.js` (نمایش فهرست کاربری‌ها در تنظیمات).
- تست: `node tests/anomaly.test.mjs` (منطق، ۴۷ مورد) · `python3 tests/ui_test.py` (مرورگر، موبایل و دسکتاپ؛ نیاز به سرور محلی روی پورت ۸۷۶۵ و Playwright).
- آستانه‌ها همه در «منو ← تنظیمات ← تحلیل مصرف و ناهنجاری» و در LocalStorage ذخیره می‌شوند (نسخهٔ ساختار: `anomaly.analysisConfigVersion`).
- مقادیر پیش‌فرض «استاندارد قانونی» نیستند. رشد دورهٔ قبل چون داده ندارد null است.

## به‌روزرسانی تب «تحلیل» (کارت‌های مالی، شاخص‌ها، نمره) + شاخص ریسک بدهی

**شاخص ریسک بدهی** = بدهی پایان دوره ÷ درآمد دوره × ۱۰۰ (به درصد). به شاخص‌های تب هوم (کارت + نقشه)، تب خروجی و کارت شاخص‌های تحلیل اضافه شد (`calc(...,"debtRisk")` در `map.js`). آستانهٔ استاندارد ندارد؛ رنگ آن در هیت‌مپ نسبی (کمتر = بهتر) است.

**کارت‌های درآمد · وصول · بدهی** (سه کارت جدا، همان الگوی کارت مصرف؛ راست‌چین، باکس عدد اصلی سمت راست):
- درآمد و وصول ۳ خط: کل + استوانهٔ سه‌بعدی شهر/روستا · سرانه مشترک ماه · متوسط روز. بدهی ۲ خط: بدهی پایان دوره + استوانه · سرانه بدهی.
- خط‌های سرانه و متوسط روز بدون درصد شهر/روستا.
- با انتخاب امور: زیر عدد اصلی «٪ از استان»، زیر سرانه «سرانه استان». با انتخاب شهر: «٪ از امور» و زیر سرانهٔ شهر، سرانهٔ استان و سپس سرانهٔ امور. زیر «متوسط روز» چیزی نمی‌آید.
- کلیک سمت راست هر خط ← نمودار میله‌ای امورها (مرتب، رنگ شهر/روستا، خط عمودی بنفش میانگین استان)؛ کلیک سمت چپ ← نمودار کاربری. drill-down: امور ← شهر ← کاربری و کاربری ← امور ← شهر.

**کارت شاخص‌ها**: ۴ مربع (دوره وصول · درصد جذب · رشد بدهی · ریسک بدهی). کلیک روی هر مربع، جدول هیت‌مپ را باز می‌کند: ستون اول همان شاخص و مرتب‌شده بر اساس آن (نزولی)، کلیک روی تیتر ستون‌ها مرتب‌سازی را عوض می‌کند. کلید الاکلنگی **امور ⇄ کاربری** بالای جدول؛ drill-down در همهٔ سطوح.

**کارت نمره**: کلیک روی دایرهٔ نمره ← لیست امورها از بحرانی‌ترین به بهترین، با وضعیت (بحرانی/هشدار/عادی) و توضیح مؤلفه‌ها؛ همان کلید الاکلنگی و drill-down.

**خط میانگین استان** در همهٔ نمودارهای میله‌ای تب تحلیل اکنون یک خط عمودی بنفش ساده است.

فایل‌ها: `js/dashboards/analytics.js` · `js/dashboards/map.js` · `js/dashboards/overview.js` · `js/dashboards/report.js` · `js/app.js` · `js/modules/analyticsEngine.js` · `css/main.css` (بلوک انتهایی «تب تحلیل — راست‌چین …»).

### اصلاحات بعدی تب تحلیل
- کارت بدهی: خط سوم «بدهی ابتدای دوره» (بدون زیرخط و بدون تفکیک شهر/روستا در خط؛ نمودار امور و کاربری مثل خط‌های دیگر).
- کارت مصرف: زیرخط «مصرف کل» و «متوسط مصرف روزانه» حذف شد؛ «سرانه مصرف» و «قیمت هر مترمکعب» فقط مقدار استان (با فیلتر امور) و استان + امور (با فیلتر شهر)، بدون شهر/روستا.
- کارت شاخص‌ها: ۴ باکس کوچک‌تر (حدود نصف ارتفاع) با عدد درشت‌تر و بولد؛ ریسک بدهی به درصد (هوم، نقشه، خروجی و تحلیل).

### تحلیل مالی — شرط «حجم مالی ناچیز» (financeEngine.js)
- `l.small` حالا `maxAbs < minMaterial && !extremePeriod` است؛ `extremePeriod` یعنی دوره وصول ≥ `max(۳×periodFloor, periodExemptDays)`. هدف: موارد با فروش جاری بسیار کم و بدهی گیرکرده (مثل امور داراب · فدامی · صنعتی) سانسور نشوند.
- پیش‌فرض `fin.minMaterial` از ۱۰۰ میلیون به ۲۰ میلیون ریال تغییر کرد؛ تنظیم جدید `fin.periodExemptDays` (پیش‌فرض ۱۸۰ روز، بازه ۶۰ تا ۳۶۵۰) در گروه «شرط‌های مطلق و حداقل‌ها» اضافه شد و در `FIN_SETTING_IDS` و `readConfig` هست.
- `FIN_CONFIG_VERSION` از ۱ به ۲ رفت تا تنظیمات ذخیره‌شدهٔ مالی کاربران قبلی به پیش‌فرض‌های جدید بازنشانی شود.
- آمار گروه‌های مقایسه همچنان فقط از رکوردهای بالاتر از `minMaterial` ساخته می‌شود (فیلد `belowMin`)، تا موارد مستثنا آمار گروه را مخدوش نکنند.

## به‌روزرسانی: فیلترها، تب تحلیل/خروجی، مالی و ناهنجاری

**همه تب‌ها**
- کلید «دستگاه‌های اجرایی و فضای سبز» از نوار بالای هوم، تحلیل و خروجی حذف شد.
- فیلترهای سه‌حالتهٔ **نیروی مسلح** (با / بدون / فقط؛ پیش‌فرض بدون) و **شهر/روستا** در یک ماژول مشترک تعریف شده‌اند (`js/modules/scopeFilters.js`) و در تب‌های مالی و ناهنجاری هم با همان ظاهر و رفتار هستند.

**تب تحلیل / آستانه‌های همبرگری**
- **ریسک بدهی** آستانهٔ استاندارد دارد: خوب تا ۵۰٪ · هشدار تا ۷۰٪ · بالاتر بحرانی (رنگ خانه‌ها و هیت‌مپ بر همین اساس). مقادیر در منوی همبرگری (گروه آستانه‌های استاندارد) قابل تغییرند.
- **نمره امور (امتیاز سلامت)** چهار مؤلفه دارد: درصد وصول ۵۰ · دوره وصول ۳۰ · ریسک بدهی ۱۵ · رشد بدهی ۵. اگر برای یک محدوده رشد بدهی نرخ معنادار نداشته باشد (بدهی ابتدای دوره صفر/ناچیز)، آن مؤلفه کنار می‌رود و وزن‌ها نرمال می‌شوند. در تب خروجی هم همین نمره و آستانه‌ها اعمال می‌شود.

**تب خروجی**
- بالای ستون مرتب‌شده یک علامت (▼ نزولی / ▲ صعودی) مثل نوار بالای ستون‌های اکسل است.
- کلید الاکلنگی **ارقام ⇄ درصد** کنار «چاپ هشدارها»: فقط ستون‌های «آمارها» به درصد تبدیل می‌شوند و سهم هر ردیف از جمع سطح بالاتر (استان ← امور ← شهر) است؛ جمع کل ۱۰۰٪.
- حالت‌های ردیف: ۱) امور ۲) شهر ۳) کاربری ۴) امور، شهر ۵) امور، کاربری ۶) امور، شهر، کاربری (تعریف: `VALID_MODES` در `report.js`). نوع سکونتگاه از فیلتر بالای صفحه می‌آید.

**تب مالی**
- نیروی مسلح لحاظ می‌شود و با کلید سه‌حالته کنترل می‌شود (پیش‌فرض بدون)؛ کلید شهر/روستا هم اضافه شد.
- نوار فیلتر هم‌شکل تب تحلیل (امور و کاربری با پاک‌کن جلوی هرکدام)؛ با انتخاب امور، شهرهای زیرمجموعه به‌صورت کلیدهای انتخابی زیر فیلتر می‌آیند.
- «نوع مشکل» و «شمارش مشکلات» اکنون همان ۱۲ علت «علت‌های اصلی مشکلات» را دارند؛ سه علت مشتق (ترکیب فروش بالا و ضعف وصول · افزایش فروش · استهلاک پیش‌دریافت و ایجاد بدهی جدید) به فیلتر و شمارش اضافه شدند (`DERIVED_CAUSES` در `financeEngine.js`).
- دکمهٔ «بازگشت» بالای جدول Drill Down؛ هدر جدول Drill Down و جدول جزئیات هنگام اسکرول ثابت می‌ماند.

**تب ناهنجاری**
- کلیدهای نیروی مسلح و شهر/روستا؛ نوار فیلتر و پاک‌کن‌ها دقیقاً مثل هوم.
- اسکرول لیست امور اصلاح شد (اسکرول داخل لیست دیگر لیست را جابه‌جا/رندر مجدد نمی‌کند و جای اسکرول بعد از هر انتخاب حفظ می‌شود).
- همه اصطلاحات انگلیسی فارسی شد (به‌جز m³)؛ راهنمای پایین صفحه نام فارسی شاخص‌ها را با معادل لاتین داخل پرانتز می‌آورد. هدر جدول «همه هشدارها» با اسکرول ثابت می‌ماند.

تست‌ها: `node tests/finance.test.mjs` · `node tests/anomaly.test.mjs`.

**تب مالی — بخش «پایش صفرها» (جدید)**
- علت مستندشده: در گروه‌هایی که میانهٔ درصد جذب صفر است (فضای سبز ۷۷٪ و سایر کاربری‌های خاص ۸۹٪ رکوردها در استان)، شرط `v < میانه` در `judge()` برای وصول صفر هرگز برقرار نمی‌شود؛ پس فضای سبز مرودشت با وصول صفر پرچم نمی‌خورد.
- راه‌حل بدون دست‌زدن به فرمول‌ها: بخش مستقل زیر کارت‌های قبلی (با خط جداکننده) و گروه جدای «پایش صفرها» در منوی همبرگری. موتور: `js/modules/zeroWatchEngine.js` (فقط می‌خواند؛ هیچ فیلدی روی رکوردهای تحلیل مالی نمی‌نویسد). UI: تابع `zwBlock` در `js/dashboards/finance.js`.
- هفت کنترل (هر کدام روشن/خاموش و با سطح نمایش اطلاعاتی/هشدار/بحرانی): فروش صفر · وصول صفر · فروش مثبت+وصول صفر · فروش صفر+بدهی مثبت · فروش و وصول صفر · بدهی بالا با وصول صفر · جذب پایین در گروه با میانهٔ صفر. تنظیم‌های جدا: حداقل مشترک، حداقل مبلغ، آستانهٔ بدهی بالا، آستانهٔ محافظ. افزودن کنترل جدید = یک مدخل در `ZW_CONTROLS`.
- تنها اثرگذار بر خروجی‌های موجود: کلید «اتصال محافظ به تشخیص ضعف وصول» (`zw.guardLink`، پیش‌فرض **خاموش**؛ فقط در `judge()` و فقط برای میانهٔ صفر).
- تست: `node tests/zerowatch.test.mjs` (داده از `tests/raw.json` = برگهٔ اول `data/1520.xlsx`؛ با `ZW_RAW` می‌توان مسیر دیگری داد).


## طراحی رابط (Design brief)

- **جهت زیبایی‌شناسی:** «دفتر حسابداری آب» — زمینهٔ کاغذی گرم (`#F3F1EC`)، متن جوهری، خطوط مویی به‌جای سایه، اعداد بزرگ با واحد کم‌رنگ و ریز؛ یک تأکید آبی نیلی (`#25406A`) به‌علاوهٔ رنگ‌های معنایی وضعیت (خوب/هشدار/نارنجی/بحرانی) که معنایشان تغییر نکرده است.
- **تایپوگرافی:** Vazirmatn با ۷ پله (۱۱ تا ۳۰px) و وزن‌های ۴۵۰/۵۶۰/۷۰۰/۸۰۰؛ ارقام tabular.
- **شبکه:** مقیاس ۸ نقطه‌ای، توکن‌ها (رنگ، فاصله، شعاع، سایه، z-index) در `css/tokens.css` و بر پایهٔ rem.
- **دسکتاپ:** کانتینر سیال تا ۱۶۸۰px (۱۹۲۰/۲۲۴۰ روی صفحه‌های بزرگ‌تر)، صفحهٔ اصلی دو ستونه (نقشه چسبان + دفتر شاخص‌ها)، تب‌ها در هدر.
- **موبایل:** نوار تب پایین با safe-area، هدف لمسی ≥۴۴px، فیلترها در شبکهٔ ۲ ستونه، جدول‌ها در کانتینر اسکرول خودشان.
- **لایه‌های CSS:** `tokens → base → layout → components → views → print` (همه در precache سرویس‌ورکر).
- محاسبات (`js/engines|data|filters|settings`) بدون تغییر؛ فقط CSS، `index.html` و بخش‌های ساخت HTML نمایشی در `js/dashboards/*` تغییر کرده‌اند (ایموجی ← آیکون CSS).
